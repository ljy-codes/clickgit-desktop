# 文档对比与冲突处理

## HTML 页面改动怎么查看（0.2.0 当前构建）

1. 在工作区选中 HTML 文件，进入 **HTML 需求 / 预览 → 静态预览 → 打开 HTML 页面对比**。
2. 独立窗口顶部显示两侧版本名称。选择“正文改动列表”，或点击“上一改动／下一改动”。
3. 页面上 **绿色为新增、红色为删除、橙色为修改**；下方始终显示所选改动的左右原文。编号仅加入预览副本，不写回文件。
4. 页面挤压时，将缩放设为 **67% / 50%**，或切换“仅看左侧／仅看右侧”；可最大化窗口。缩放同时作用于两侧。
5. “需求描述”抽屉等隐藏区域不会执行脚本展开。隐藏正文仍列入改动详情；找不到可见标记时会明确提示，请看下方原文或主界面的“需求对比”。

**注意**：这是正文文本节点高亮，不是像素级或 DOM 结构比较；样式、属性、脚本变化请查看源码。“未发现正文差异”不代表整个文件相同。过大或过于复杂的材料会明确降级，不强行计算。高亮可能轻微改变页面排版；连续多个变化文本节点可能合为一项。需求对比默认选中首个有变化的章节。

新构建标识为 `2026-09-10-source-inline-highlight`，产品版本仍为 **0.2.0**。诊断日志入口、独立进程超时保护及静态安全限制保持不变。

## 源码中具体改了哪些字

工作区左右对比、HTML“源码对比”和“需求对比”均自动显示字符差异，不需要开启开关：

- 修改行用浅底色，左侧删除字符用红色，右侧新增字符用绿色。例如 `电池接插件更换` → `电池接插件00更换`，右侧只高亮新增的 `00`。
- 中文、emoji 以及长 HTML 行中的局部小改动均按实际位置标记；普通复制仍保留原内容，不带颜色或辅助标记。
- 内容很长时可横向滚动查看。“上一差异／下一差异”按变更块导航，不是逐个字符跳转。
- 复杂字符比较超过预算会提示“部分仅行级”，此时仍可查看整行变化；2 MiB、20000 行、单行 8192 字符上限保持不变。
- 这是只读比较，不修改、格式化或保存原文件。主动用鼠标选中文字时，系统选区颜色可能暂时覆盖差异底色，取消选区即可。

## 看修改内容

工作区选中文件，默认打开左右对比。未暂存文件：左边是暂存版本，右边是当前文件；已暂存文件：左边是上次提交，右边是本次暂存内容。新增文件原文为空。行号、增删标记、颜色显示变化，上一处/下一处跳转；原始差异保留在另一个标签中。

支持 UTF-8（含 BOM）文本，不自动改编码。超过安全大小/复杂度、二进制或特殊文件会显示限制，不把空白当作真实文件。左右视图只读，不可用显示用占位空行覆盖源文件。

## 看历史

提交历史选中记录 → 查看内容变化。合并提交会要求选择父版本，第一个父版本通常是合并前接收内容的分支。也可输入两个分支/提交哈希进行比较。历史/跨版本重命名暂按旧文件删除、新文件新增分别查看，不声称已做语义追踪。

## 合并分支

1. 先提交或妥善贮藏全部修改，包括未跟踪文件。
2. 分支 → 选中来源 → 比较并合并到当前分支。
3. 逐个查看来源差异。**这不是预测的最终合并结果**；分支变化后旧确认失效。所有变化文件加载成功后才能勾选确认；不支持的文本或二进制变化，请改用外部 Git 工具，本入口不会开始合并。
4. 勾选确认并开始合并。应用会修改工作文件，但不自动提交；即使可快进也等待检查，完成时生成合并提交。
5. 有冲突：工作区双击冲突文件，或点击“解决所选文件冲突”。
6. 逐块取舍或手动编辑，保存草稿不等于解决；处理完成后标记解决并暂存。
7. 工作区 → 检查结果并完成合并 → 逐个查看实际暂存内容 → 勾选并确认完成合并。加载中、失败或超出显示预算时不可确认；加载失败可以重试。
8. 合并后再次展示合并前后的版本对比；不会自动推送。

此流程针对“分支”入口的普通合并，不改变“拉取”已有策略；变基、拣选、删除/重命名、二进制等复杂冲突不要强行文本覆写。来源术语须结合操作类型理解，不把 index stage 2/3 一概解释成“我的/远程的”。

## HTML 产品文档

选中 `.html` / `.htm` 后点击 **HTML 需求对比 / 页面预览**；放大对比和历史/分支比较窗口也有入口：

- **需求对比**：提取隐藏 PRD 正文，按章节及表格文字展示变化，点“定位原源码”查看实际文件位置。不能识别专用正文时会提示退化为页面文字；动态生成内容没有执行。相同正文不代表样式、属性或脚本相同。
- **源码对比 / 原文定位**：保留完整源码比较；原文定位只读，可切换自动换行，不会格式化或保存。特殊 Unicode 段落分隔符不使用原文定位；超出预算明确拒绝，辅助正文显示不能绕过合并确认门槛。
- **静态预览**：点击“打开左右静态预览（独立窗口）”后，在另一个窗口左右显示传入版本。预览使用独立进程，审阅界面仍可操作；关闭审阅或切换基准也会关闭预览。仅保留允许的 HTML 与内嵌样式，控件不交互，不运行脚本、不联网、不加载图片/外部 CSS/字体或任意本地资源。不是完整交互原型，隐藏内容请看需求对比。
- **预览无响应**：启动超过 25 秒，或加载后 8 秒无心跳，程序会停止本次预览并提示；可以重试或继续源码/需求对比。如果公司环境拒绝建立进程隔离，预览会明确停用，不要求关闭安全软件。
- **问题排查**：进入“设置 → 查看 / 复制诊断信息”，或审阅窗口的诊断入口，刷新后复制当前快照。日志包含构建标识、实际配置位置、结构校验结果、预览失败分类/退出码和异常代码位置，不包含 HTML 正文、密钥或原始异常消息。可能包含用户名和本机路径，分享前请检查。日志不自动上传；磁盘不可写时仍可复制当前内存快照，但关闭程序后可能无法保留。
- **冲突结果**：在三栏编辑窗口点“检查 HTML 结果”，可选择当前侧/对方侧/共同基准，与尚未保存的结果副本比较。该窗口不保存、不暂存、不提交；编辑后重新打开才更新检查副本。

疑似冲突标记会直接提示；重复 ID、解析限制等详情点击 `?` 查看。采用双方只是文本拼接，必须人工核对表格、节点与脚本。当前不提供完整 HTML5/JS 语法验证、业务规则自动一致性判断或交互脚本预览。

## 文件保护与边界

- 编辑器打开后，其他工具修改文件或索引，会拒绝覆盖，重新打开后再处理。
- 保存草稿可保留冲突标记；标记解决和完成合并会检查标记，疑似合法正文也应人工复核。
- 保存失败不会自动回退或把结果说成成功；暂存失败时检查实际文件内容后再操作。
- 保存失败时编辑窗口保留文本；若文件/索引已变化，先复制整理结果另存，再重新打开冲突文件，不盲目重复覆盖。
- 校验采用重复快照检查，不能与其他 Git/编辑器构成跨进程原子事务；合并期间不要在其他工具同时改同一仓库。最后校验到 Git 获取锁之间仍有小窗口。
- 取消本次合并会撤销本轮合并和冲突编辑，操作前请另存需要保留的材料。
- 未知编码、Word/PDF、链接、子模块和复杂删除/重命名冲突不在文本编辑首批支持范围。
