# 问题排查

适用版本：0.2.0，构建 `2026-09-10-source-inline-highlight`。

## 先确认实际启动的程序

1. 退出旧 ClickGit，查看快捷方式“目标”指向的可执行文件。
2. 在目标安装目录直接启动 `ClickGit.exe`。
3. 在设置的诊断入口核对构建标识和实际配置路径。

拖拽快捷方式不会复制程序及依赖。免安装包必须整体解压，保留 `_internal`
和 `runtime` 等目录；不能只复制 EXE。不同盘符不能证明使用了不同配置。

## 提示“设置文件结构版本不受支持”

这是应用配置保护状态，不是 Git 仓库只读。当前 Windows 使用当前用户的
`%APPDATA%\ClickGit`，安装版与免安装包没有独立便携数据目录策略。

- 先通过诊断确认实际配置路径、结构校验结果和构建标识，不只看同名文件。
- `settings.json` 是设置，`projects.json` 是项目列表，不要混淆。
- 不直接改 `schema_version`，不删除项目、仓库或账号凭据。
- 备份实际读取的配置后再判断恢复方案。应用不自动覆盖不支持的配置；
  同版本重装也不能证明已更换配置。
- 保存失败时本次会话可能已应用偏好，但没有落盘；查看提示并检查写入条件。

本轮未实现独立便携配置目录或自动结构迁移，也未单独确认所有公司环境
配置警告的根因。用户验收通过不应扩展为这些问题已经自动修复。

## 看不清改动

- **源码对比**：左删红、右增绿，浅底代表修改行。长行可横向滚动；
  主动选择文本后系统选区可能覆盖差异色，取消选择即可。
- “部分仅行级”表示字符匹配超过预算，而非没有变化。
- **静态预览**：选顶部改动项，结合下方左右文本详情；隐藏需求不靠执行
  JavaScript 展开。没有正文差异不代表 CSS、属性或脚本相同。

## 预览异常、无响应或进程退出

预览使用独立进程。查看失败提示，可以关闭预览后继续源码/需求对比。
不要关闭安全软件、Chromium 沙箱或放开业务 HTML 脚本来绕过故障。

进入“设置 → 查看 / 复制诊断信息”，刷新后检查：

- 构建标识与实际配置路径；
- 预览开始、就绪、关闭、失败/超时分类；
- 进程退出码和代码位置。

日志仅在本机保存，不自动上传；可能包含本机路径或用户名，分享前请检查。
不需要发送业务 HTML 全文、密码、密钥或完整仓库。突然断电/强制结束、
磁盘不可写等情况可能丢失尚未落盘的记录。
