## 主要变化

- Windows 新增按当前用户安装的标准安装版，并保留免安装便携版。
- Windows 包内置 PortableGit 2.55.0.windows.3，不要求用户安装 Git、
  Python 或 Qt。
- PyInstaller 运行依赖收纳到 `_internal`，应用目录只保留用户需要看到的
  程序、运行时、许可证和说明文件。
- 新增 macOS Apple Silicon 与 Intel 双架构自动构建和结构校验。
- 新增第三方许可证 SHA-256 锁定、PortableGit 许可证检查和发行门禁。
- Release 发布改为草稿暂存、附件冲突拒绝和双平台全部成功后公开。

## 测试结果

- Windows 完整自动化测试：84 项通过。
- Windows 便携目录冒烟：界面启动检查通过，内置 Git 返回
  `git version 2.55.0.windows.3`。
- Windows 安装生命周期：静默安装、已安装应用冒烟、许可证核验和静默卸载
  均通过。
- macOS ZIP：由 GitHub Actions 分别校验 ZIP CRC、`.app` 可执行文件、
  Mach-O 格式和 CPU 架构。
- 首次 `release-v0.2.0` 工作流因 GitHub Runner 使用 LF、Windows 工作区
  使用 CRLF，许可证原文的字节级摘要不一致而停止。摘要规则已改为统一
  LF 后计算，并通过 `release-v0.2.0-retry1` 触发不可变重试。
- `release-v0.2.0-retry1` 的两个 macOS 架构均通过，Windows Runner 因
  `cp1252` 控制台无法输出测试中文路径而停止。校验器已对控制台输出进行
  编码降级，并通过 `release-v0.2.0-retry2` 再次触发不可变重试。
- `release-v0.2.0-retry2` 对应工作流 `34122844552` 的 Windows x64、
  macOS arm64、macOS x64 和最终发布任务全部通过。

## 已知问题

- Windows SmartScreen 可能显示未知发布者。
- macOS Gatekeeper 可能阻止首次直接启动，可在 Finder 中右键选择“打开”。
- macOS 需要系统可执行路径中存在 Git；Git LFS 功能需要额外安装 Git LFS。
- 超大仓库的历史记录当前最多加载 200 条。
- 文本冲突编辑器按 UTF-8 保存，二进制冲突需要外部工具处理。

## 回滚方式

1. 不覆盖或移动 `windows-v0.2.0`、`mac-v0.2.0` 和
   `release-v0.2.0` 标签。
2. 新版本出现问题时，停止推荐 v0.2.0，但保留失败产物、日志和哈希清单。
3. 核验 v0.1.0 对应附件仍可下载后，引导用户回退到
   `windows-v0.1.0` 或 `mac-v0.1.0`。
4. 修复后使用更高版本号发布，不覆盖已经公开的 Release 附件。
