# ClickGit Windows 桌面工具设计说明

**日期：** 2026-07-24  
**状态：** 已确认  
**目标用户：** 不使用 Git 命令行、只通过图形界面完成操作的 Windows 用户

## 1. 目标

在 `D:\专用工具\git工具` 中创建一个功能完整的 Windows Git 桌面工具。程序以 `ClickGit.exe` 为入口，内置 PortableGit，不依赖目标电脑预装 Git、Python 或其他开发环境。

工具支持任意标准 Git 仓库，包括 GitHub、GitLab、Gitee 和公司私有 Git 服务，兼容 HTTPS 与 SSH。所有常用操作都必须通过按钮、菜单、向导和对话框完成。

## 2. 核心原则

- 默认面向新手，主界面只展示高频、安全操作。
- 强制推送、硬回退、清理和删除分支等操作集中在“高级操作”。
- Git 操作在后台执行，界面不得因网络或大仓库操作而卡死。
- 不解析面向人类的普通终端输出，优先使用 Git 的机器可读格式。
- 不在配置文件、日志或仓库中明文保存密码、访问令牌和私钥。
- 危险操作执行前创建恢复点，并提供可视化恢复入口。
- 同一仓库的写操作串行执行，避免并发修改仓库状态。

## 3. 技术方案

采用以下技术组合：

- Python 3
- PySide6 / Qt Widgets
- PortableGit
- PyInstaller 打包 Windows 可执行程序
- pytest 进行单元和集成测试
- Qt Test 或 pytest-qt 进行关键界面测试

选择该方案的原因：

- Qt 提供稳定的 Windows 原生桌面交互和完善的多面板控件。
- Python 适合实现 Git 命令编排、结构化解析和文件差异处理。
- PortableGit 可保证程序在未安装 Git 的电脑上直接运行。
- 相比 Electron，运行内存和发布结构更可控。
- 相比 Tauri/Rust，首版开发和后续维护成本更低。

## 4. 总体架构

```text
PySide6 界面
    |
    v
应用用例层
    |
    +--> 仓库与操作状态管理
    +--> 凭据与 SSH 管理
    +--> 安全恢复管理
    +--> 冲突解决流程
    |
    v
Git 服务层
    |
    +--> 命令构造器
    +--> 后台任务队列
    +--> Git 输出解析器
    +--> 错误分类器
    |
    v
内置 PortableGit
```

### 4.1 模块边界

- `ui`：窗口、对话框、列表、差异视图和用户交互，不直接执行 Git。
- `application`：组织打开仓库、提交、同步、合并、恢复等完整用例。
- `git`：构造命令、执行进程、解析结果并返回结构化模型。
- `merge`：三方冲突模型、内容选择、手工编辑和继续/放弃流程。
- `recovery`：隐藏恢复引用、临时快照、清理文件隔离和恢复记录。
- `credentials`：Windows 凭据管理器、HTTPS AskPass 和 SSH 密钥管理。
- `storage`：应用配置、最近仓库、操作日志和恢复索引。
- `models`：仓库状态、文件变化、提交、分支、标签、远程和任务状态。

## 5. 主界面

界面采用工作型桌面布局：

- 顶部：当前仓库、当前分支、获取、拉取、推送和任务状态。
- 左侧：工作区、提交历史、分支、标签、暂存记录、远程仓库、高级操作。
- 中间：文件、提交、分支或远程对象列表。
- 右侧：差异、提交详情、属性或操作预览。
- 底部：提交说明、提交按钮、错误与后台任务入口。

程序启动后直接进入仓库工作界面。未选择仓库时显示最近仓库、打开、克隆和新建仓库入口，不创建宣传型首页。

## 6. 功能范围

### 6.1 仓库管理

- 打开本地仓库。
- 克隆远程仓库。
- 初始化新仓库。
- 最近仓库和收藏仓库。
- 验证普通仓库、裸仓库和 Worktree 路径。

### 6.2 工作区与提交

- 查看已修改、新增、删除、重命名、冲突和未跟踪文件。
- 按文件暂存、取消暂存。
- 按差异块暂存、取消暂存。
- 查看工作区、暂存区和提交之间的差异。
- 丢弃单个文件或选定差异块的修改。
- 提交选中文件。
- 修正上次提交。
- 编辑提交说明并校验空说明。

### 6.3 远程同步

- 获取、拉取和推送。
- 展示本地分支相对上游的领先/落后数量。
- 设置上游分支。
- 添加、修改和删除远程地址。
- 支持多个远程仓库。
- 支持推送标签和删除远程分支。

### 6.4 历史与版本比较

- 图形化提交历史和分支线。
- 按作者、说明、哈希、日期和文件筛选。
- 查看提交详情和提交文件。
- 比较任意两个提交、分支或标签。
- 查看单个文件历史。
- 反向提交、挑选提交和创建分支。

### 6.5 分支、标签和暂存记录

- 新建、切换、重命名和删除分支。
- 合并和变基。
- 交互式变基，包括重排、合并、修改和删除提交。
- 创建、删除和推送标签。
- 创建、应用、弹出、重命名和删除暂存记录。
- 暂存记录支持包含未跟踪文件。

### 6.6 冲突解决

- 自动识别合并、变基、挑选提交和应用暂存记录产生的冲突。
- 三栏查看基础版本、本地版本和远程版本。
- 一键选择本地、远程或两边内容。
- 提供可编辑的最终结果区域。
- 支持逐冲突块处理。
- 全部解决后提供“继续操作”按钮。
- 提供“放弃合并”“放弃变基”等与当前流程匹配的按钮。

### 6.7 高级与恢复功能

- 软回退、混合回退和硬回退。
- 强制推送默认使用租约检查。
- 清理未跟踪文件前展示完整预览。
- Reflog 浏览和提交恢复。
- 误删分支恢复。
- 仓库完整性检查和垃圾回收。
- 补丁创建、导入和应用。
- `.gitignore` 可视化编辑。

### 6.8 扩展 Git 功能

- 子模块初始化、更新、添加、移除和状态查看。
- Worktree 创建、打开、锁定、移除和清理。
- Git LFS 检测、安装、跟踪规则和拉取对象。

## 7. 操作数据流

1. 用户点击界面操作。
2. 界面生成带类型和参数的应用请求。
3. 应用层执行前置校验和安全策略。
4. Git 服务层构造参数数组，不拼接 Shell 命令字符串。
5. 后台任务队列启动内置 `git.exe`。
6. 输出解析器生成结构化结果。
7. 应用层根据结果刷新状态或进入冲突、认证、恢复流程。
8. 界面显示结果，并记录脱敏后的操作日志。

读取状态时优先使用以下稳定格式：

- `git status --porcelain=v2 -z`
- 自定义 `git log --format` 和记录分隔符
- `git for-each-ref --format`
- `git diff --numstat`、`--name-status` 和补丁输出
- `git remote get-url`

## 8. 后台任务与并发

- 每个仓库维护独立任务队列。
- 状态、历史和差异读取任务可以并发，但应合并重复刷新请求。
- 提交、切换、拉取、合并、变基、回退等写操作必须串行。
- 写操作进行时禁用会造成状态冲突的按钮。
- 网络任务支持取消；取消后重新检测仓库状态。
- 程序异常退出后，下一次启动检查未完成的合并、变基和挑选提交状态。

## 9. 认证与 SSH

### 9.1 HTTPS

- 使用独立 AskPass 图形对话框接管 Git 的凭据询问。
- 用户可选择将凭据保存到 Windows 凭据管理器。
- 日志中对 URL 用户信息、令牌和认证头进行脱敏。

### 9.2 SSH

- 选择已有私钥。
- 生成新密钥并设置注释和可选口令。
- 一键复制公钥。
- 测试远程连接。
- 支持用户已有的 SSH Agent。
- 私钥内容不进入应用配置和日志。

## 10. 安全与恢复

危险操作执行前根据影响类型创建保护：

- 提交图变更：创建 `refs/clickgit/recovery/<timestamp>` 隐藏引用。
- 工作区覆盖：创建包含未跟踪文件的临时快照。
- 清理未跟踪文件：先列出清单，再移动到应用恢复目录。
- 删除分支：记录分支名称和提交哈希。
- 强制推送：使用远程租约检查，远程变化时中止。

恢复记录保存在 `%APPDATA%\ClickGit\recovery`，界面展示来源仓库、操作类型、时间、内容和恢复按钮。恢复数据支持用户手动清理，并可设置保留天数和最大空间。

程序必须校验仓库根目录和文件真实路径，禁止通过符号链接或相对路径逃逸到预期目录之外。

## 11. 错误处理

常见错误转换成中文业务提示：

- 认证失败。
- SSH 主机校验失败。
- 远程不存在或无权限。
- 非快进推送。
- 本地存在未保存修改。
- 分支已在其他 Worktree 使用。
- 合并或变基冲突。
- 仓库锁文件存在。
- 磁盘空间不足。
- PortableGit 文件缺失或损坏。

错误弹窗提供直接处理按钮。原始技术信息放在可展开详情中，普通操作不要求用户理解命令行输出。

## 12. 本地数据

应用数据根目录为 `%APPDATA%\ClickGit`：

```text
ClickGit/
  settings.json
  repositories.json
  logs/
  recovery/
  ssh/
  cache/
```

- 配置文件采用版本化 JSON 格式。
- 原子写入配置，避免程序退出导致文件损坏。
- 缓存可以删除并自动重建。
- 凭据不写入 JSON。
- 日志默认按日期和大小轮转。

## 13. 发布方式

### 13.1 便携版

```text
ClickGit/
  ClickGit.exe
  runtime/
    git/
    qt/
  resources/
```

用户解压后双击 `ClickGit.exe` 使用。采用目录式发布，避免每次启动都解压大型 PortableGit。

### 13.2 安装版

额外提供 `ClickGit-Setup.exe`：

- 安装到用户目录或 Program Files。
- 创建开始菜单和桌面快捷方式。
- 提供卸载入口。
- 卸载时默认保留用户配置和恢复数据，并允许用户选择删除。

## 15. 兼容性

- 支持 Windows 10/11 64 位。
- 支持普通仓库、裸仓库和 Worktree。
- 支持 HTTPS 和 SSH 远程地址。
- 不修改仓库提交格式和服务端协议。
- 不要求仓库安装额外 Hook。
- 所有恢复引用使用独立命名空间，避免覆盖用户分支和标签。

## 16. 主要风险

- PortableGit、Qt 和 Python 运行时会使发布包较大。
- 超大仓库的历史图和差异加载需要分页、缓存和取消机制。
- 不同 Git 服务的认证提示存在差异，需要覆盖 GitHub、GitLab、Gitee 和标准私有服务。
- Git LFS、子模块和 Worktree 会扩大测试矩阵。
- 自动恢复不能替代远程备份，界面必须准确展示可恢复范围。
- Windows 防病毒软件可能对未签名的新 EXE 发出警告，正式分发时应考虑代码签名。

## 17. 验收标准

- 未安装 Git、Python 和 Qt 的 Windows 电脑能够双击启动。
- 用户无需输入 Git 命令即可完成仓库初始化、克隆、提交、推拉、分支和冲突处理。
- 常用操作全程有进度、成功结果或可执行的中文错误提示。
- 危险操作默认隐藏并有二次确认和恢复入口。
- 凭据、令牌和私钥不会明文进入配置或日志。
- 自动化测试覆盖核心解析、仓库写操作、冲突和恢复流程。
- 打包产物能够稳定处理中文、空格和长路径仓库。
